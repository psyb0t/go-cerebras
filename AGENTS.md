# go-cerebras

Unofficial Go client for the Cerebras Inference API. If you only want to use the client from an agent, read [.agents/skills/go-cerebras/SKILL.md](.agents/skills/go-cerebras/SKILL.md) instead; this file is about changing the code.

## Architecture

Nearly all the code is generated:

`scripts/fetch-spec.sh` → `api/openapi.yaml` → oapi-codegen (`config.yaml`) → `client.gen.go`.

- `scripts/fetch-spec.sh` reads `openapi_spec_url` from the `.stats.yml` of `Cerebras/cerebras-cloud-sdk-python` and downloads that Stainless URL. The URL carries a content hash, so it is never hardcoded.
- No patch step: oapi-codegen takes the OpenAPI 3.1 spec as published.
- `gen.go` holds the `//go:generate` lines in order.

## Stack

- Go 1.26.10, one package at the module root.
- oapi-codegen v2 and golangci-lint run through `go tool`, pinned in `go.mod`.
- Runtime dependency: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`: package doc and `go:generate` steps.
- `config.yaml`: oapi-codegen config.
- `client.gen.go`: generated models and client.
- `client_test.go`, `example_test.go`: httptest-backed tests and the README example.
- `scripts/`: spec fetch, lint and security scan scripts the Makefile runs.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The spec lists no server. Callers pass `https://api.cerebras.ai`; the README and the skill say so.
- Messages, the chat response and the model list response are `anyOf` unions. A spec change that reorders union members renames the generated `...Content0`/`...Content1` helpers.
- CI skips the generate drift check, because the upstream spec changes on its own schedule. Regenerate locally and commit the result.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
